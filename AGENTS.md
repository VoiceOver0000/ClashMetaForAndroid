# AGENTS.md

## Scope

This file applies to the entire `ClashMetaForAndroid` repository.

## Repository Map

- `app/`: Android application module, activities, foreground logcat service, quick settings tile, dynamic shortcuts, app stores, and client-side remote/service helpers.
- `design/`: UI layer. Contains `Design` classes, data binding layouts, adapters, custom views, dialogs, preference builders, themes, strings, drawables, and UI models.
- `service/`: background/VPN/service layer. Contains `ClashService`, `TunService`, profile processing, Room database, documents provider, remote Binder interfaces, Clash runtime modules, and service stores.
- `core/`: native bridge and Clash/Mihomo integration. Contains Kotlin bridge/model APIs, C/C++ JNI bridge under `src/main/cpp`, Go wrapper code under `src/main/golang`, and FOSS Go flavor code under `src/foss/golang`.
- `common/`: shared constants, compatibility helpers, stores, parcel helpers, logging, and global application scope.
- `hideapi/`: compile-only Android hidden API stubs.
- `fastlane/metadata/android/`: store listing metadata.
- `.github/workflows/`: CI/release/update automation.
- `.github/patch/`: Go toolchain patches applied by CI before building.
- `.idea/codeStyles/`: committed project code style settings.
- `core/src/foss/golang/clash`: Git submodule for MetaCubeX Mihomo/Clash core, configured in `.gitmodules`.

## Build Configuration

- Gradle project name: `ClashMetaForAndroid`.
- Included Gradle modules: `:app`, `:core`, `:service`, `:design`, `:common`, `:hideapi`.
- Gradle wrapper: `gradle/wrapper/gradle-wrapper.properties`, Gradle `8.10.2`.
- Android Gradle Plugin: `8.8.0`.
- Kotlin: `2.1.0`; Kotlin code style is `official`.
- Java source/target compatibility: `JavaVersion.VERSION_21`.
- CI uses Temurin Java `21`; prefer Java 21 over the older README mention of OpenJDK 11.
- Android SDK: `compileSdk`/`targetSdk` `35`, `minSdk` `21`.
- NDK: `29.0.14206865`.
- Supported ABIs: `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64`; app releases enable ABI splits plus a universal APK.
- Flavors: `alpha` and `meta`, both in flavor dimension `feature`; `alpha` is default.
- Build types: `debug` adds `.debug` version suffix; `release` minifies and shrinks only the app module.
- Current version is defined centrally in root `build.gradle.kts`: `versionName = "2.11.30"`, `versionCode = 211030`.

## Build And Test Entry Points

Use the Gradle wrapper from the repository root.

- Primary CI/debug artifact build: `./gradlew --no-daemon app:assembleAlphaRelease`.
- Release artifact build: `./gradlew --no-daemon app:assembleMetaRelease`.
- Debug variants are available through standard Android Gradle tasks such as `app:assembleAlphaDebug` and `app:assembleMetaDebug`.
- Unit/instrumentation test source sets are not present in this checkout; verify task availability before relying on `test`, `connectedAndroidTest`, or module-specific test tasks.
- Standard Android lint tasks should be treated as available through AGP, but no custom lint workflow is defined.
- `app` assembly tasks depend on `downloadGeoFiles`, which downloads GeoIP/GeoSite/ASN/MRS assets into `app/src/main/assets`; do not run assemble tasks when network or workspace writes are disallowed.
- `clean` removes root build outputs and also deletes `app/src/main/assets`; do not run it if preserving downloaded assets matters.
- CI setup also updates CA certificates and copies `ca-certificates.crt` into the Clash submodule tree before building.

## Local Build Prerequisites

- Initialize submodules before building: `git submodule update --init --recursive`.
- Provide Android SDK path in root `local.properties`, for example `sdk.dir=/path/to/android-sdk`.
- Optional `local.properties` keys:
  - `custom.application.id=com.example.app`
  - `remove.suffix=true`
- Release signing is read from ignored root `signing.properties`; if absent, release builds fall back to debug signing.
- `release.keystore` exists in the repository; do not modify signing material unless explicitly asked.
- CI uses Go `1.26` from MetaCubeX's Go release base and applies patches in `.github/patch/`.
- `core/src/main/golang/go.mod` and `core/src/foss/golang/go.mod` declare Go `1.20` but rely on the local Mihomo replacement and CI's patched Go toolchain.

## Generated, Cache, And External Paths

Do not edit generated or cache output by hand:

- `.git/`, `.gradle/`, `build/`, `bin/`, `obj/`, `.cxx/`, `debug/`, `Debug/`, `release/`, `Release/`, `node_modules/`.
- `app/src/main/assets/` is ignored and generated by `downloadGeoFiles`.
- `service/build/generated/ksp/<variant>/kotlin` and `service/build/generated/ksp/<variant>/java` are generated by KSP.
- Android data binding classes such as `DesignMainBinding` are generated from XML layouts.
- Native build outputs and Go plugin outputs are generated under module build directories.
- Treat `core/src/foss/golang/clash` as an external submodule unless the task explicitly targets the Mihomo core.

## Module Responsibilities

- Keep activity orchestration in `app/src/main/java/com/github/kr328/clash`.
- Keep reusable UI rendering/state binding in `design`; activities should delegate view setup to `Design` classes.
- Keep service process behavior, profile persistence, VPN/runtime modules, and Binder service implementations in `service`.
- Keep native-facing models and bridge wrappers in `core`; avoid making app/service modules call JNI directly when `Clash` or `Bridge` wrappers already exist.
- Keep cross-module constants, compatibility shims, shared stores, parcel helpers, and logging in `common`.
- Use `hideapi` only for compile-time stubs for hidden Android APIs.

## Kotlin And Android Conventions

- Follow the committed IntelliJ/Android Studio Project code style in `.idea/codeStyles/Project.xml`.
- Kotlin uses official style with project-configured star imports for `java.util`, `kotlinx.android.synthetic.*`, and `io.ktor.*`.
- Prefer the existing coroutine style:
  - Activities usually extend `BaseActivity<D : Design<*>>` and implement `override suspend fun main()`.
  - Long-running activity loops use `while (isActive)` with `select`.
  - UI writes are wrapped in `withContext(Dispatchers.Main)`.
  - File/database/network work is wrapped in `Dispatchers.IO`.
  - CPU list/filter work commonly uses `Dispatchers.Default`.
- `BaseActivity` owns `MainScope`, design lifecycle cancellation, day/night theme application, broadcast events, and activity result helpers; reuse it for new screens.
- `Design<R>` owns the root `View`, `requests: Channel<R>`, `Surface`, and snackbar helper; use request enums to send UI intents back to activities.
- Use Android data binding consistently: add layout variables and update generated binding properties from `Design` classes.
- Preserve the pattern of `DesignXBinding.inflate(context.layoutInflater, context.root, false)` for screen layouts.
- Use `Channel.UNLIMITED` or `Channel.CONFLATED` only when it matches nearby patterns and backpressure behavior is intentional.
- For settings, prefer existing store delegates in `common.store.Store` and module-specific stores such as `UiStore`, `AppStore`, `TipsStore`, and `ServiceStore`.

## Service And IPC Conventions

- Service-side Binder contracts live in `service/src/main/java/com/github/kr328/clash/service/remote` and use `@BinderInterface` from KAIDL.
- Generated KAIDL sources are wired by `service/build.gradle.kts`; do not edit generated Binder code.
- Client-side remote wrappers live in `app/src/main/java/com/github/kr328/clash/remote` and `app/src/main/java/com/github/kr328/clash/util/Remote.kt`.
- Foreground services use notification channel helpers in service modules; keep Android foreground service type and manifest declarations in sync.
- `service` runs core services and providers in the `:background` process; be careful with process-local singletons and stores.
- Room database schema is in `service/data`; migrations live in `service/data/migrations`. Add migrations when changing persisted entities.

## Native And Go Conventions

- `core/src/main/cpp/CMakeLists.txt` builds the `bridge` shared library and links it with Go output named `clash`.
- `core/build.gradle.kts` wires `golang-android` output into CMake per flavor/build type/ABI.
- Go build source set package name is `cfa/native`; output library filename is `libclash.so`.
- Both `alpha` and `meta` Go source sets use tags `foss`, `with_gvisor`, and `cmfa`, with additional source from `core/src/foss/golang`.
- Kotlin native entry points are centralized in `core/bridge/Bridge.kt` and wrapped by higher-level `core/Clash.kt`.
- JNI-facing classes and callbacks are annotated with `@Keep`; preserve these annotations when changing native bridge APIs.
- When adding or changing native APIs, update all three layers together: Go/C bridge, JNI declarations in `Bridge.kt`, and Kotlin wrapper/model code.

## Resources And Localization

- Base app resources live in `app/src/main/res`; most screen layouts, strings, themes, icons, and reusable UI resources live in `design/src/main/res`.
- Service/common modules also define their own strings and IDs.
- Existing localizations include Chinese, Chinese Hong Kong, Chinese Taiwan, Russian, Japanese, Korean, and Vietnamese depending on module.
- When adding user-facing strings, add them to the owning module's `values/strings.xml`; update localized files when feasible or leave clear English fallback through the base resource.
- Keep manifest labels and authorities consistent with `${applicationId}` and the constants in `common/constants`.

## Manifest And Public Interfaces

- Default app ID is `com.github.metacubex.clash`; flavor suffixes are `.alpha` and `.meta` unless `remove.suffix=true`.
- Root namespace for `app` is `com.github.kr328.clash`; libraries use `com.github.kr328.clash.<module>`.
- Public automation actions are:
  - `com.github.metacubex.clash.meta.action.START_CLASH`
  - `com.github.metacubex.clash.meta.action.STOP_CLASH`
  - `com.github.metacubex.clash.meta.action.TOGGLE_CLASH`
- Profile import schemes are `clash://install-config?url=...` and `clashmeta://install-config?url=...`.
- Keep exported activities, receivers, providers, permissions, and foreground service types explicit in manifests.

## Dependency Management

- Version catalog is `gradle/libs.versions.toml`; add new Maven dependencies there instead of hardcoding coordinates in module build files.
- Root `build.gradle.kts` configures repositories and common Android settings for all subprojects.
- Existing repositories are `mavenCentral()`, `google()`, and `https://raw.githubusercontent.com/MetaCubeX/maven-backup/main/releases`.
- Avoid introducing new repositories unless required and explicitly justified.
- Go module replacement is managed through local `replace` directives and the update-dependencies workflow.

## CI And Release Automation

- Pull requests and pushes to `main` run `.github/workflows/build-debug.yaml`, which builds `app:assembleAlphaRelease` and uploads unsigned APK artifacts.
- Pushes to `main` and manual dispatch run `.github/workflows/build-pre-release.yaml`, which builds `alpha` release APKs and publishes `Prerelease-alpha`.
- Manual release dispatch runs `.github/workflows/build-release.yaml`, rewrites root Gradle version fields from the `vX.Y.Z` tag, builds `app:assembleMetaRelease`, tags, and uploads release APKs.
- `.github/workflows/update-dependencies.yaml` updates the Mihomo submodule and Go modules, then opens an `Update Dependencies` PR.
- Do not alter workflow version bumping, signing, or upload paths without checking the corresponding artifact paths under `app/build/outputs/apk/<flavor>/release`.

## Editing Guidelines

- Keep changes scoped to the owning module. Do not move behavior across `app`, `design`, `service`, `core`, and `common` boundaries unless the task requires it.
- Do not hand-edit Gradle-generated, KSP-generated, data binding-generated, native build, or downloaded asset files.
- Do not change `.gitmodules`, Go replacement paths, or the Mihomo submodule pointer unless the task is specifically dependency/core update work.
- Do not commit local-only files such as `local.properties`, `signing.properties`, `tracker.properties`, `.vscode/`, logs, or CMake/Gradle caches.
- Preserve LF line endings except Windows batch files, which are CRLF per `.gitattributes`.
- Prefer existing helpers such as `intent`, `withClash`, `withProfile`, `showExceptionToast`, store delegates, `ticker`, and compat extensions before adding new utilities.
- When changing persisted profile data, Room entities, or service stores, update migration/default behavior and consider legacy migration impact.
- When changing UI behavior, update the matching `Design` class, XML layout, strings, and activity request handling together.
- When changing public automation intents, URL schemes, provider authorities, permissions, or manifest exported state, update README automation documentation too.

## Verification Expectations

- For build-affecting changes, the closest repository check is the relevant Gradle assemble task, but remember assemble downloads geo assets and writes build outputs.
- For service/database changes, inspect Room entity/DAO/migration consistency and generated KSP wiring.
- For native bridge changes, verify Kotlin `external` signatures, JNI/C functions, Go exports, and model serialization names stay aligned.
- For UI changes, verify data binding variable names match layout usage and `Design` update methods run on the main dispatcher.
- If tests are requested, first confirm available Gradle test tasks because this repository currently has no checked-in `test` or `androidTest` source tree.
